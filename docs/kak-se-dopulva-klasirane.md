# Как се дописва класиране (ATP, WTA, Ф1, Ф2, Ф3)

Таблиците с класирания не идват от API. Стоят в обикновени JSON файлове в
`src/data/standings/` — по един на класиране:

```
src/data/standings/atp.json   ← ATP, мъже, сингъл
src/data/standings/wta.json   ← WTA, жени, сингъл
src/data/standings/f1.json
src/data/standings/f2.json
src/data/standings/f3.json
```

## Един ред

Всеки участник е един ред на един ред — нарочно, за да се дописва и чете лесно:

```json
{ "pos": 11, "name": "Casper Ruud", "country": "Norway", "points": 3120, "move": -2 }
```

| поле | какво значи |
| --- | --- |
| `pos` | позицията в класирането |
| `name` | името както се пише официално, с диакритиките (`Świątek`, `Muchová`) |
| `country` | държава с пълно име на английски, не с код |
| `points` | точки, като цяло число без запетайки — запетайките ги слага сайтът |
| `move` | промяна спрямо предишното издание: `2` е нагоре с две, `-2` е надолу с две, `0` е без промяна, `null` е **непроверено** |

`move: null` не значи „не се е местил“. Значи „не сме го сверили“ и на
страницата излиза тире. Ако наистина е задържал мястото си, се пише `0` и
излиза `=`. Разликата е важна: тирето не твърди нищо, нулата твърди.

## Бутонът „още“

Страницата показва първите десет и слага бутон **Show 10 more**, който вади по
още десет. Не се настройва нищо — бутонът се появява сам щом редовете станат
повече от десет и изчезва, когато свършат. Таблицата спира на сто; ако във
файла има повече редове, сайтът реже на стотния и го казва под таблицата.

Нещо важно за търсачката: тя гледа **всички** редове, не само показаните. Ако
търсиш номер 74, ще го намери, без да натискаш „още“ седем пъти.

Без JavaScript (така четат и повечето AI обхождачи) цялата таблица излиза
наведнъж, а бутонът се скрива. Тоест всичките сто реда стоят в HTML-а от самото
начало — не се дозареждат — и се индексират.

## Докъде стига списъкът

```json
"confirmedThrough": 10,
"listTo": 100,
```

`listTo` е докъде **трябва** да стигне списъкът. Докато редовете са по-малко,
под таблицата сайтът сам обяснява, че списъкът е до N, а целта е 100. Така
кратката таблица не изглежда като грешка.

## Пропуснати позиции

Ако някъде числата не могат да се сверят, позициите **не се измислят**. Слага
се ред за пропуск:

```json
{ "gap": "4 – 8", "note": "Being re-checked — see below" }
```

Излиза като сив ред на мястото си и се обяснява в `footnote`. Точно това стана
с ATP 4–8: намерените числа идваха от класиране „на живо“ по време на турнир,
което не съвпада с официалното понеделнишко. По-добре видима дупка, отколкото
уверено сгрешено число — грешна таблица се цитира и после се помни.

## Откъде се взимат числата

Официалното класиране на ATP и WTA се публикува всеки понеделник. Взима се от
самите федерации (`atptour.com/en/rankings/singles`,
`wtatennis.com/rankings/singles`) и **не** от табло „live ranking“ — то се мени
по време на турнирите и не е същото.

Сверява се два пъти, от два различни източника. Ако не съвпадат, редът става
`gap`.

## След промяна

```bash
npm run build
```

Датата в `asOf` се сменя на ръка — тя е това, което казва на читателя колко
стар е снимката. Ако числата са нови, а датата стара, таблицата лъже.
